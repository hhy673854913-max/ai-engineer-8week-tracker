## 上午 09:00–11:30 · 包装方法论

### 1. 面试官看 README 的顺序（前 30 秒）

1. 一句话：这是什么、解决什么问题
2. 截图 / 演示链接（有就赢一半）
3. 量化数据（指标、成本、延迟）
4. 架构图
5. 快速启动

**前 30 秒没看到 1–3，后面写得再好也没人看。**

### 2. README 模板

```markdown
# 项目名

> 一句话定位：给谁、解决什么问题、有什么不同。

![demo](docs/demo.gif)

## 效果
| 指标 | 数值 | 说明 |
| --- | --- | --- |
| 检索 hit-rate@5 | 0.86 | 50 条评估集 |
| P95 延迟 | 2.1s | 本地 2C2G |
| 单次成本 | ¥0.003 | 含检索与生成 |

## 架构
（mermaid 图）

## 技术选型与理由
| 决策 | 选择 | 理由 | 放弃了什么 |

## 快速开始
```bash
cp .env.example .env
docker compose up
```

## 已知局限
- 只支持单轮，多轮指代会错
- 专有名词分词不准时 BM25 会漏

## 迭代计划
- [ ] 多轮改写
- [ ] 语义缓存
```

**"已知局限"不是减分项**，是成熟度信号。面试官会顺着它问，你正好展示思考。

### 3. 架构图：mermaid 就够了

```mermaid
flowchart LR
    Q[问题] --> R[混合检索] --> RR[重排] --> G[生成] --> A[答案+引用]
```

**不要放花哨的架构图**，清晰的 5 个框比 20 个框的"企业级图"更有说服力。

### 4. 技术博客怎么选主题

| 主题 | 素材来源 | 传播性 |
| --- | --- | --- |
| 《从零手写 RAG 的取舍》 | Day 12–15 | 高（有代码有数据） |
| 《LangGraph 状态机实践》 | Day 24–29 | 中高 |
| 《把活动交付从 3 天压到 1 天》 | M3 | 高（有业务价值） |
| 《MCP Server 开发踩坑》 | Day 26–28 | 中（时效性强） |

写作结构：**结论前置 → 问题背景 → 我的做法 → 数据 → 踩坑 → 适用边界**。
不要写成"教程流水账"。

### 5. 作品集首页

一个简单页面汇总三个项目（你的前端主场）：
- 三个卡片：定位、指标、demo 链接、GitHub
- 一段 100 字的自我介绍（"11 年前端 + AI 应用"）
- 联系方式

**部署到 GitHub Pages 即可**，零成本。

## 下午 14:00–16:30 · 实战

### 任务 1 · 三个 README（120 min）

每个项目按模板写，重点补三样东西：
1. **一个真实 badcase**（现象 → 定位 → 修复 → 数据变化）
2. **一个取舍决策**（为什么不用 X）
3. **一个数字**（指标 / 成本 / 延迟）

### 任务 2 · 演示素材（40 min）

- GIF：用 `ScreenToGif` 或录屏转 GIF（≤ 5MB，否则 GitHub 加载慢）
- 截图：关键界面 2–3 张
- demo 链接：M2 的公网地址

### 任务 3 · 两篇博客（60 min）

先写《从零手写 RAG 的取舍》：
- 开头给结论："如果你只有 100 条文档，别上向量库，numpy 足够"
- 中间给三个取舍：分块策略、混合检索、阈值拒答
- 结尾给数据：hit-rate 从 0.65 → 0.86

### 任务 4 · 作品集页（20 min）

一个 `index.html`，三张卡片，部署到 GitHub Pages。**这是你简历上的"个人主页"链接。**

## 代码思考（写进 `logs/day-38.md`）
