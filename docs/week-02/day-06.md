## 上午 09:00–11:30 · 理论输入

### 1. 原则一：指令清晰（Clear Instructions）

模型不是读心术。它只能依据你给的文字做概率推断，所以"清晰"= **消除歧义**，具体是四件事：

| 要素 | 模糊写法 | 清晰写法 |
| --- | --- | --- |
| 角色 | "帮我总结" | "你是游戏运营周报编辑，读者是部门负责人" |
| 任务 | "分析一下" | "提取 3 条本周关键结论，每条 ≤ 30 字" |
| 格式 | "给我结果" | "输出 JSON：{\"conclusions\": [\"...\"]}" |
| 边界 | （无） | "只依据给定材料，材料没写的标注『未提及』" |

四个动作，写 prompt 时逐条检查：
1. **用分隔符隔离输入**：`"""..."""`、`<article>...</article>`、`### 材料开始 ###`
2. **明确输出格式**，最好给一个字段清单或一条示例
3. **明确"不知道"怎么办**：这是降低幻觉最便宜的手段
4. **明确角色与读者**：同一份内容给老板和给玩家，写法完全不同

### 2. 原则二：给模型思考时间（Give the Model Time to Think）

模型是**逐 token 生成**的：先输出的内容会成为后续推理的上下文。
所以"直接要结论"等于逼它在没有草稿的情况下心算。

三种给时间的方式：

```text
# A. 显式步骤
先列出材料中的 5 个要点，再从中选出最重要的 3 个，最后写成 50 字摘要。

# B. 先分析后结论（结构化思考字段）
先输出 "analysis" 字段写推理过程，再输出 "answer" 字段写结论。

# C. 零样本 CoT
让我们一步一步思考。
```

**注意**：C 对推理类任务有效，对抽取类任务可能反效果（模型开始编故事）。
而且如果下游要结构化输出，**思考过程不该和结果混在一个 JSON 里**——用 `analysis` / `result` 两字段，
或者分两次调用（Day 08 会做这个取舍）。

### 3. 提示词的"三不"反模式

| 反模式 | 为什么错 | 改法 |
| --- | --- | --- |
| 一次要求 10 件事 | 注意力被摊薄，每件都做不好 | 拆成多步，或分多次调用 |
| 全大写 + 大量感叹号施压 | 边际收益递减，还占 token | 用结构（标题、列表）代替音量 |
| 把示例写成和任务不同的格式 | 模型会模仿示例的**格式**，不是内容 | 示例必须与目标输出同构 |

### 4. 一条被低估的原则：**可评测**

写 prompt 时就应该想好"怎么判断这次改动是变好还是变坏"。
没有评估集的 prompt 迭代就是玄学。今天先建立最小习惯：**准备 10 条固定样本 + 一个打分标准**。

## 下午 14:00–16:30 · 实战

### 任务 1 · 三类任务的对照实验（90 min）

准备 10 条真实材料（新闻、活动公告、玩家评论各若干），对每个任务写三版 prompt：

```python
PROMPTS = {
    "v1_模糊": "总结下面这段内容，提取主题和情感。\n{text}",
    "v2_清晰": (
        "你是游戏社区运营分析师。阅读下面的玩家评论，完成三件事：\n"
        "1. 用不超过 40 字概括这条评论的主要诉求；\n"
        "2. 判断情感倾向，只能选：正面 / 中性 / 负面；\n"
        "3. 列出 1-3 个关键词。\n"
        "只输出 JSON：{\"summary\": \"\", \"sentiment\": \"\", \"keywords\": []}\n"
        "评论：\n<review>{text}</review>"
    ),
    "v3_清晰+思考": (
        "……（同 v2，但在输出 JSON 前增加一步）\n"
        "先在 analysis 字段写 2 句话分析依据（引用原文关键词），再填 summary/sentiment/keywords。\n"
        "JSON 结构：{\"analysis\": \"\", \"summary\": \"\", \"sentiment\": \"\", \"keywords\": []}"
    ),
}
```

跑 10 条 × 3 版，人工按三档打分（准确 / 可用 / 不可用），统计通过率。

### 任务 2 · 找"最小充分提示词"（40 min）

从 v3 开始**逐句删减**，每次删一句，看通过率是否下降。记录"哪句不能删"。
这一步能让你真正理解每句话的作用，而不是堆砌模板。

### 任务 3 · 建立本仓库的 prompt 实验台（50 min）

```python
# code/week02/day06_prompt_basics.py
CASES = [{"id": "c1", "text": "..."}, ...]

def run_experiment(prompt_id: str, cases: list[dict]) -> list[dict]:
    results = []
    for c in cases:
        raw = chat(PROMPTS[prompt_id].format(text=c["text"]), temperature=0)
        results.append({"id": c["id"], "prompt": prompt_id, "raw": raw})
    return results
```

输出 CSV 到 `output/prompt_exp_YYYYMMDD.csv`，方便你横向对比（也可以用 Excel 手写评分）。

落到 M1 上，这张表不是一次性作业：Day 08 迭代 M1 抽取模板时直接复用 `run_experiment`，把样本换成 20 条资讯正文、打分标准不变，用来对比 v1/v2；到 M1 交付你手上会有一张『prompt 版本 × 字段准确率 × 单条成本』的表，面试时它比『我会写提示词』有说服力得多。
