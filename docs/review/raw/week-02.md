# week-02 审校结果

## 周总评

本周是 M1 里程碑周，但岗位落点是"一天扛四天"：只有 Day 08 把练习直接做成了 M1 的抽取模板（并一路延续到 Day 10 的流水线），Day 06 的对照实验台与 Day 07 的模式库都没有交代自己在 M1/M2 链路里的位置（Day 09 至少有一句"为 Day 11 的向量检索准备数据"接住了后文），读者做完仍是"练手作品"而不是"项目零件"；同时本周出现一处跨周前向引用——Day 10 让读者按 SimHash + embedding 做去重取舍，而 embedding 要到 Day 11 才讲、SimHash/海明距离全文没有一句定义，属于"要动手却没人给定义"。建议给 06/07 的每份产出一句话锚到 M1 的某一步或面试叙述，并把 Day 10 的去重补齐定义与实现任务。

## day-06 · 提示词两大原则

- **P1 · 任务 3 · 建立本仓库的 prompt 实验台** ｜ 问题：整节只写了"输出 CSV 到 `output/prompt_exp_YYYYMMDD.csv`，方便你横向对比（也可以用 Excel 手写评分）"，既没说这套实验台之后由谁消费，也没交代本日样本（"玩家评论 / 活动公告"）与 M1 抽取的资讯正文是两套素材域——按此写法，读者花 50 分钟建的表在 Day 08 迭代 M1 模板时不会被复用，等于一次性作业。 ｜ 建议补写：在这句之后插入："这张表不是一次性作业：Day 08 迭代 M1 抽取模板时直接复用 `run_experiment`，把样本换成 20 条资讯正文、打分标准不变，用来对比 v1/v2；到 M1 交付你手上会有一张『prompt 版本 × 字段准确率 × 单条成本』的表，面试时它比『我会写提示词』有说服力得多。"

## day-07 · 文本转换、对话系统与提示词模式库

- **P1 · 4. 提示词模式库（你自己的一版）** ｜ 问题：本节只有一句"下面是我建议的 8 个模式，你要做的是**给每个模式补上自己的语言和例子**"，全篇没有交代这套库在岗位上的用途——M1/M2/M3 的哪段 prompt 会从它取用、面试被问"你怎么写 prompt"时拿什么举证，"模式库"因此容易被读成抄一份表格。 ｜ 建议补写：在 8 模式表格下方插入："这份库不是背诵清单：M1 的抽取模板、M2 的问答 prompt、M3 的工具调用 system 都从这 8 个模式里取用，『我的实测效果』一栏就是它们的踩坑记录；面试时能说出『我有一份 8 个模式的库、每个都做过对照』，比『我熟悉提示词工程』更有说服力。"

## day-10 · 里程碑 M1：智能资讯简报 v2

- **P0 · 4. 去重的两层** ｜ 问题：本节要求"用 SimHash / MinHash 做指纹，海明距离 ≤ 3 视为重复；或用 embedding 余弦 > 0.92"，并给出"先用 SimHash 粗筛，冲突的再上 embedding"的取舍，但 SimHash、MinHash、海明距离三个词一句解释都没有，embedding 更要到 Day 11 才第一次讲；而下午四个任务（采集 / 抽取 / 排序 / 报表）里没有去重这一步，架构图与 `report.json` 的 `after_dedup` 却都依赖它——读者会卡在"这一步到底怎么写、用什么实现"。 ｜ 建议补写：在"工程取舍"之前插入："SimHash 是一种不用调 API 的局部敏感哈希：把正文按特征词加权压成一个 64 位指纹，两篇稿子越像两个指纹的**海明距离**（不同的二进制位数）越小，≤ 3 基本可判同一事件，10 万条也能秒级跑完。embedding 是把文本映射成向量、用余弦比相似度（Day 11 详讲，更准但按量计费），所以先用 SimHash 粗筛，只把可疑的对送进去复核。" 并在下午补一步"任务 2.5 · 去重（30 min）：`dedup(items) -> (kept, dup_report)`，报表里的 `after_dedup` 就来自它的返回值"。
