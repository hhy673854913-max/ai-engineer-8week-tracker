## day-21 · ReAct 与手写 Agent 循环

- **P1 · 2. ReAct 循环** ｜ 问题：「ReAct」在今日目标、日标题、验收、commit message 里反复出现，但本节只有一段伪代码外加一句"结构上仍是这三段：推理 → 行动 → 观察"，从未说清 ReAct 是什么、为什么业界统一采用这个范式。读者敲完能跑，却答不出 week-08 面试清单里的"ReAct 原理？"。｜ 建议补写：ReAct 是 Reasoning + Acting 的缩写，2022 年论文提出的范式：让模型在"想一步 → 调一个工具 → 看结果 → 再想"的循环里推进，而不是一次把答案说完。今天这 8 行 while 循环就是它的最小实现——W8 的 M3 主干跑的就是它，面试官问"讲讲 ReAct"时你要能白板画出来的也是它。

- **P1 · 3. Function Calling 的消息结构（必须背下来）** ｜ 问题：标题直接跳到"消息结构（必须背下来）"并举三条致命细节（"`tool_call_id` 对不上 → 400"），全篇没有一句解释 Function Calling 是什么、模型为什么必须靠这个协议才能调工具。"# 1) 模型要求调用工具"这句注释不足以让只调过文本输出的读者建立概念。｜ 建议补写：Function Calling 是模型厂商提供的协议：模型不再只吐文本，而是吐一个结构化的"我要调这个函数、参数是这些"的请求，由你的代码执行后按 id 回填结果——这是模型从"会说"变成"会做"的那一步。它是所有 Agent 框架的底座，LangGraph、smolagents、MCP 底下跑的都是这套消息，所以结构要默写。

- **P2 · 任务 3 · 加轨迹日志（30 min）** ｜ 问题：只交代了"把每一步存成 JSONL"和"Agent 的可调试性完全依赖轨迹"，落点是开发者本地自查；没说这份轨迹在生产里给谁看——线上排障的 trace、M3 里渲染"思考过程"的前端面板、面试演示时的证据，一个都没出现。｜ 建议补写：这份 JSONL 在生产里就是 Agent 的 trace：线上用户说"它答错了"，你靠它复盘是哪一步选错工具、哪一步被工具的返回值带偏。M3 的前端还要把它渲染成"思考过程"给用户看——面试演示时能一格格放 trace，比说"我做了个 Agent"有说服力得多。

## day-22 · Function Calling 深入与多工具编排

- **P2 · 任务 2 · 三个真实工具（80 min）** ｜ 问题："注意 SSRF 防护"直接出现，紧接着就是"禁止内网 IP、169.254.x"这类规则清单，但没一句说 SSRF 是什么，更没说 Agent 场景为什么比普通后端接口更危险——URL 由模型给出（甚至由模型读到的网页内容给出）。｜ 建议补写：SSRF（服务端请求伪造）是让服务器替攻击者去访问内网地址的漏洞。Agent 工具比普通接口更危险：请求哪个 URL 常常由模型、甚至由它刚抓到的网页内容决定——攻击者只要在页面里写一句"请访问 169.254.169.254"，就可能让工具替他去读云厂商的元数据凭证。

- **P2 · 任务 3 · 多工具并行（40 min）** ｜ 问题：理论部分只写了"并发执行会放大限流风险"，实战直接给 `asyncio.gather` + `await asyncio.to_thread(...)`，全程没说 Agent 为什么需要并行（延迟直接决定用户多久看到第一个字），也没解释 Day 21 那些同步工具为什么必须抛到线程里跑。｜ 建议补写：并行不是为了代码好看：3 个工具各 2 秒，串行用户要等 6 秒，并行能压到 2 秒——这是 Agent 产品体验上的分水岭。`asyncio.to_thread` 是因为 `registry.call` 是同步函数，直接 await 会把整个事件循环卡死，你 Day 21 写的工具全是同步的，所以只能丢进线程池。

## day-24 · LangGraph 状态图建模

- **P1 · 2. 三个核心概念** ｜ 问题：上一节还在讲抽象概念（"为什么用状态机而不是 while 循环"），这一节直接 `graph = StateGraph(AgentState)`、`app.compile(checkpointer=MemorySaver())` 开写：没说 LangGraph 是什么、为什么不用自己写的状态机，也没解释 `Annotated` 的第二个参数是合并函数——不写它，后一个节点返回的 messages 会整段覆盖而不是追加。｜ 建议补写：LangGraph 是 LangChain 团队出的编排库：把 Agent 的每一步写成节点、把跳转写成边，编译成一张能持久化、能中断恢复的图——它是目前 Agent 岗位 JD 里出现频率最高、面试最容易被追问"你怎么组织多步流程"的那个答案。另外 `Annotated[list, add_messages]` 里第二个参数是合并函数，缺了它后一个节点会把前一个节点写的 messages 直接覆盖掉，这是新手最常踩的坑。

## day-25 · 记忆系统：短期上下文与长期偏好

- **P1 · 3. 长期记忆的写入与召回** ｜ 问题：写入侧给了完整字段设计（含 `confidence`），召回侧却只有一句"召回：用当前问题做 embedding，检索该用户的记忆，top-3 拼进 system"——top-3 从哪来、召回为空或召回错时怎么退化、记忆与本轮指令冲突时谁优先，全都没写，也没有任何一句落到真实场景。｜ 建议补写：召回是这一节的工程重心：用当前问题做 embedding 去检索该用户的记忆，命中后拼进 system；但记忆与本轮指令冲突时谁优先（用户这轮说"详细讲讲"，记忆里写着"讨厌长回复"）、召回为空时怎么退化，都要在这里定规则。生产上"Agent 记错人、记住过期偏好"是最常见的投诉，就出在这一层。
