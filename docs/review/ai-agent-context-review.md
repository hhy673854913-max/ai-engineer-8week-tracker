## 二、四个系统性病因

### 1. 术语先于定义出现

同一个概念在标题、表格、代码里反复出现，就是没有一句"它是什么"：

| 概念 | 首次出现 | 什么时候才有解释 |
| --- | --- | --- |
| Pydantic | day-02 §2（只有"会做校验"半句） | 从未 |
| LCEL | day-16 §3 | 从未（day-17 继续用） |
| JSON-RPC 2.0 | day-26 §5 | 从未 |
| RAGAS | day-32 §1（标题就是它） | 从未 |
| LLM-as-judge | day-31 §5（标题就是它） | 从未 |
| SimHash / 海明距离 | day-10 §4 | 从未（还要动手实现） |

P0 全部出自这一类：**读者会在这一步直接卡住，后面的内容再正确也接不上。**

### 2. 动机停在"技术内部"，不是"岗位后果"

课程很擅长解释"机制上为什么这样"，但少了一步"不这么做，在工作里会发生什么"：

- 流式只讲"首字延迟 8s → 0.8s"，没讲长输出会撞网关 60s 空闲超时、Agent 的检索/工具状态只能靠流推给前端；
- 异常分层只讲"CLI 翻译成退出码"，没讲它第 5 周会变成工具的错误契约——分层错了，Agent 会对必败工具死循环烧配额；
- `logging` 只讲"print 的替代"，没讲一行日志要能串成 trace（trace_id / span / tokens / tool / latency）。

### 3. 落点是"课程内部链接"，不是"简历与生产"

"Day 05 会用到""Day 33 展开"是**课程导航**，不是**岗位能力**。区别在于：前者告诉你去哪一页，后者告诉你这段能写进简历哪一行、对应面试哪一问、上线后会挡掉哪类故障。

最典型的是 week-05：5 天里 0 次提到 M1/M2/M3，尽管 roadmap 写明本周产出就是 M3 的骨架；ReAct 和 Function Calling 两个标题级概念全周没有定义，而它们恰好都在 week-08 的面试清单里。

### 4. 前端存量优势没被显式接上

转型者的差异化恰恰在这里，但课程只在 day-20（引用溯源界面）和 day-04（`EventSource`）沾了一下：

- SSE 的客户端消费你本来就会（`EventSource` / `fetch` + `ReadableStream`）；
- `v-html` 的 XSS 攻击面、流式接口的前后端契约、React 侧的 loading/取消态，都是现成优势；
- 这些本该写成"这半边你已经会，只需要补服务端那一半"，而不是当成新知识从零讲。

## 五、写作规范（以后每篇按这个落笔）

每个知识点，在给出代码之前先回答四问，一句话即可：

1. **是什么**：不用术语解释术语。「Chroma 是 pip 装完就在进程内跑的嵌入式向量库」。
2. **为什么是我**：不学它，你会在哪一步卡住 / 你的前端经验哪一段能接上。
3. **用在哪**：落到具体文件或步骤（`M2 的 store.py`、`M3 的 search_kb 工具`），不是"工作中会用到"。
4. **面试怎么答**：一句话标准答案，读者可以直接背。

### Before / After 样例（day-02，你指出的那处）

**Before**——只有口诀，没有定义和位置：

> - `dataclass`：进程内部的数据容器，零校验、零依赖、快。
> - `Pydantic`：**边界**上的数据——外部输入、LLM 输出、HTTP 请求体。会做类型转换 + 校验 + 报错信息。
> 一句话记忆：**"数据从外面进来，就用 Pydantic。"**

**After**——补上"是什么 + 三个落点 + 判断线"：

> **Pydantic 是 Python 的数据校验库**：你把字段声明成 `class X(BaseModel)`，实例化那一刻它就把输入逐个校验、必要时转换（`"3"` → `3`），不合法直接抛 `ValidationError` 并指到具体字段；同一份声明还能导出 JSON Schema、直接序列化成 JSON（`model_dump_json`）。它的位置在**系统边界**：外面进来的数据不可信，进门先过它。
>
> 在 Agent 工程里它有三个躲不开的落点——① 模型返回的 JSON（day-05 结构化输出、day-22 工具参数），不校验就带着脏字段往下跑；② 工具的函数 schema，Function Calling 要求你提供 JSON Schema，`BaseModel.model_json_schema()` 直接生成；③ FastAPI 的请求体（day-34），422 报错和 OpenAPI 文档都是它给的。
>
> 所以判断线不是"dataclass 旧、Pydantic 新"，而是：**数据在自己进程内部流转用 dataclass，跨过信任边界（模型、用户、网络）就用 Pydantic。**

差别不在于字数，而在于读者读完能不能回答"我现在该在哪一行写它"。
