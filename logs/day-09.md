## 代码思考题回答

> 题目见课程文档的「代码思考」小节，答 2–3 题即可，写出你的判断和依据。

1. 核心大字两者都能识别，真正的差异在 小字覆盖率 ：high 更倾向输出更多文字（纸卷、印章），low 更倾向于保守（只给确定的）
2. 大图使用base64会有体积膨胀，所以要先使用pillow进行图片压缩处理，API 网关限制请求体 10~50 MB 。如果批量很容易就撞到上限
3. 理论上会有差异，第一张图会锚地模型注意力，后续图片会基于第一张图的描述进行描述。但是目前模型已经抹平了差异
4. 逐字的缘故，模型把图片里模糊/错误的字，自动"纠正"成它认为正确的字，而不是忠实转录原样。对于发票收据，药品说明书，法律文书等不能变的场景是致命的
策略是
Prompt 加约束
temperature=0
字段级置信度（每个字/词附带 confidence，低置信度人工复核）
用专用 OCR 模型
结果再用规则校验一遍（身份证号校验位、发票金额格式等硬规则拦截）
人工复核
5. 有可能场景和色调为不同字段导致无法query失败，向量的核心是语义空间相近
假设图库里有一张暖色调生日花束，模型生成的描述是：
{
  "scene": "一束粉色玫瑰和白色满天星的花束，包装纸为浅粉色纱纸",
  "style": "暖色调",
  "search_tags": ["玫瑰", "粉色", "花束", "鲜花", "满天星", "浪漫"]
}
怎么解决
生成时补场合标签
Prompt 里加`"usage_tags": ["适合场合，如 生日/婚礼/纪念日"]` ，让模型主动推断
query 扩展
把"生日图"扩展成`"生日 花束 玫瑰 暖色调 礼物"` ，拉齐语义分布
多字段加权检索
`style` 字段单独检索，`scene` 单独检索，再加权合并
query 改写
先用 LLM 把用户的"暖色调生日图"改写成`"粉色玫瑰 暖色调 花束"` ，再做向量检索
