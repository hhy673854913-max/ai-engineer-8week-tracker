## 学到什么（费曼式，3 条以内）

1.文本转换、把风格拆成可执行的维度，要提供具体的可量化的说明，例如
不是说"写得活泼一点"：而是说
- 人称：统一用"你"，不用"您"
- 句长：每句不超过 20 字
- 用词：可用"冲""稳了""上车"，禁用"尊享""礼遇"
- 保留：所有数值、时间、奖励名称不得改动
- 输出：只给改写结果，不要解释
2.文本扩展、是让模型补齐没有的内容，要适当提高温度
- 温度调高（0.7–1.0）增加多样性
- 必须给"素材边界"：只能使用以下信息，缺的不要编
- 适合"生成 5 个候选让人选"，不适合"生成唯一正确答案"
3.对话系统：system 到底管什么，
控制输入安全，防止模型被攻击。
管理一些不变的内容、例如
- 角色：用户、助手、系统
- 规则rule：不能使用敏感词、不能使用法律术语等
- 状态：用户是否登录、是否注册等
管理一些变化的内容、例如
- 上下文：用户 previous turn 的内容
- 系统反馈：模型 previous turn 的内容

第 1 级：黑名单正则（微秒级，先拦明显的）
INJECTION_PATTERNS = [
    r"忽略.*(规则|指令|之前)",
    r"系统提示词",
    r"system\s*prompt",
    r"假装你是.*开发者",
    r"你现在不是.*客服",
    r"DAN|jailbreak",
]

def is_injection(text: str) -> bool:
    return any(re.search(p, text, re.IGNORECASE) for p in INJECTION_PATTERNS)

第 2 级：LLM 分类（毫秒级，判断"这是什么"）
不让主对话模型自己判断自己 ：

CLASSIFY_PROMPT = """判断下面这句话的意图类别，只输出标签：
- compensation_query（问游戏补偿/活动/充值到账）
- account_issue（账号问题）
- injection_attempt（索取系统提示/要求忽略规则/伪装开发者）
- other（其他）

<text>{user_input}</text>

标签："""

def route(user_input: str) -> str:
    resp = client.chat(
        [{"role": "user", "content": CLASSIFY_PROMPT.format(user_input=user_input)}],
        temperature=0.0,
        max_tokens=10,
    )
    return resp.content.strip()

滑窗（Sliding Window）
机制 ：只保留最近 N 轮对话，超出的直接丢弃。
长程依赖断裂 ——用户第 1 轮说"我要订去北京的票"，第 5 轮说"改签到明天"。滑窗只保留最近 2-3 轮，"北京"和"改签"的锚点已丢失，模型只能瞎猜或反问。
事实型问答 ——用户问"我上次说的那个 API 密钥是什么？"，密钥在 10 轮前，滑窗早把它清掉了。模型要么编造（幻觉），要么说"你没提过"。
多轮约束累积 ——"不要用 Python""要兼容 Windows""预算 1 万"三条约束分散在 5 轮里，滑窗丢掉前两条，模型按最新一条生成，结果违背早期要求。

失效的本质 ：它假设"越近越重要"，但对话里关键信息常常前置（用户需求、约束条件）。

摘要（Summarization）
机制 ：定期用 LLM 把早期对话压成一段摘要，替换原始历史。
数字/专名失真 ——摘要模型把"10 月 25 日 14:00 维护 3 小时，补偿 200 钻石"压成"10 月下旬维护，补偿一些钻石"。日期、金额、ID 这类精确 token 最容易在压缩中丢精度或变形（200→"一些"）。
否定与条件丢失 ——"不是 Python，是 Go；除非性能不够才考虑 Rust"被压成"用 Go 或 Rust"，否定词和条件分支被抹平。
细节不可追溯 ——摘要后原始文本没了，用户追问"你确定是 200 不是 100？"，系统无法回溯验证，只能重复摘要里的错误。
失效的本质 ：摘要是有损压缩，它保"大概意思"，丢"精确字符"和"逻辑修饰"。

检索（Retrieval / RAG）
机制 ：把历史切成 chunk 存向量库，每轮根据当前 query 检索最相关的片段注入上下文。
指代消解失败 ——用户说"那上面写的补偿规则呢？"，检索用"补偿规则"做 embedding，可能命中知识库里的通用规则，但用户实际指 3 轮前对话里的特定规则。embedding 不理解"那"指代什么。
跨片段关联断裂 ——"对比方案 A 和方案 B 的成本"需要同时检索 A、B 两段，单 query 检索可能只召回 A。多跳推理（A 依赖 B 依赖 C）几乎必挂。
时效性冲突 ——用户 5 轮前说"预算 1 万"，刚刚改口"其实 5 万也行"。向量检索按相似度召回，可能把旧的 1 万和新的 5 万同时塞进上下文，模型选哪个看运气。
失效的本质 ：检索是"相关性"匹配，不是"因果性"理解。它找"像的"，不找"对的"。

滑窗 | 闲聊、短平快问答 | 用户开始说"刚才说的""之前那个" 
摘要 | 长文档分析、代码审查 | 涉及精确数字、日期、否定条件 
检索 | 知识库问答、多文档综合 | 指代词（那/这个/

5. 先怀疑 prompt，有可能是 prompt 问题，本身指代不明不准确
- 指令存在多义 ："总结成 3 点"——是"3 个要点"还是"3 句话"？模型每次可能按不同理解走。
- 约束未排他 ："用简洁口语"——"简洁"和"口语"可能指向不同风格，模型在不同上下文下权重不同。
- 输入触发不同路径 ：样本里数字位置、专名密度不同，模型注意力分布改变，生成路径分叉。

验结果 归因 修复方向 
同输入多次不同 | prompt | 歧义 | 消歧：示例、结构化、约束排他 | 
换输入才不同 | 输入边界 | 补样本、加拒答兜底 | 
某模型独有不稳 | 模型敏感 | 调 | prompt | 适配或换模型 | 
结构化后稳定 | 格式自由度 | 强制 | JSON/模板
